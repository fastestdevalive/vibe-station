## Root cause

- **`file-watch-scoping`** → `rust/vst-daemon/src/server.rs:437-447` (`worktree_path_resolver`) resolves a watch target only by walking `project.worktrees` looking for a matching id; it never falls back to `project.absolute_path`. A direct session's id can never match, so `handle_file_watch`/`handle_tree_watch` (`rust/vst-ws/src/handlers/file_watch.rs:106-111`, `tree_watch.rs:110-115`) would error `"Worktree '...' not found"` if ever called. The frontend knows this and pre-emptively no-ops: `web-ui/src/hooks/useSubscription.ts:106` and `:215` both `return undefined` when `scope === "project"`, so `file:watch`/`tree:watch` are never even sent for a direct session. `FileWatcher` itself (`rust/vst-ws/src/streams/file_watcher.rs:194-293`, `notify`-crate based, ignore-matched against `.git`/`node_modules`/nested `.gitignore`s at `:14-31,73-114`) is directory-agnostic — the gap is purely in the resolver/wiring layer, not the watcher. Root cause of bugs **#1 and #3**.
- **`git-status-worktree-only`** → `web-ui/src/api/client.ts:919-931` (`listChangedPaths`) is hardcoded to `/worktrees/:id/changed-paths` — unlike `fileBase()` (`client.ts:101-104`), it never branches on `FileScope` to hit `/projects/:id/...`. Backend has no such route at all: `rust/vst-daemon/src/server.rs:525-569`'s route table defines `/projects/:id/tree|file-list|files/*path` but no `/projects/:id/changed-paths|diffstat|commits|gutter|diff`. `WorktreeRoutes::changed_paths` (`rust/vst-routes/src/worktrees.rs:1620-1631`) additionally requires a matching `project.worktrees` entry to resolve `wt_path`, so even a same-shaped call with a direct-session id would 404. Frontend also explicitly disables the UI: `FileTreeSidebar.tsx:115-116` forces `scope = "none"` when `isProject`, and `:303-310`/`:333-338` skip the changed-paths fetch entirely (`QuickOpen.tsx:132` has the same `scope !== "worktree"` guard). The underlying `git status --porcelain=v1 -z -uall` invocation (`worktrees.rs:1722-1761`) needs only a directory path, not worktree metadata — `ProjectRoutes::tree` (`rust/vst-routes/src/projects.rs:1159-1227`) already proves `project.absolute_path` is a valid root for the same class of operation. Root cause of bugs **#2 and #4**.
- **`commits-route-worktree-only`** → `WorktreeRoutes::commits` (`worktrees.rs:1809-1839`) is a plain paginated `git log -n{limit} --numstat` from HEAD (`list_commits`, `git.rs:443-455`) — it is **not** a `base..head` range query. `base_sha` is used only to *annotate* each returned commit with `is_on_branch` (`git.rs:530-537`); `list_commits` already accepts `base_sha: None`, in which case every commit is `is_on_branch: true`. There is simply no `/projects/:id/commits` route registered, so `VcsPanel` 404s for direct sessions instead of degrading. Root cause of bug **#5**.
- **Shared pattern**: file watching, tree watching, git status/gutter, and commits listing were all wired end-to-end only along the `worktree_id → worktree record → worktree path` path; the parallel `project_id → project.absolute_path` path already exists for read-only tree/file/list endpoints but was never extended to watching, git status, or commits. None of the underlying primitives are worktree-specific — this is a routing/wiring gap, not an architectural one.

## VCS tab / commits pagination decision

**Resolved: show all commits, unfiltered, paginated — no synthetic base ref.** This is not a divergence from the worktree case; it's what the worktree case already does, minus one annotation:

- `WorktreeRoutes::commits` already calls `list_commits(wt_path, limit, base_sha)`, which runs a plain `git log -n{limit}` from HEAD with no range — `base_sha` only flags which commits are `is_on_branch` for `VcsPanel`'s collapsed "from `<base>`" grouping (`VcsPanel.tsx:308-322`).
- `ProjectRoutes::commits` can be `list_commits(&project.absolute_path, limit, None)` verbatim — every commit comes back `is_on_branch: true`, no synthetic base derivation needed.
- Monorepo size is bounded the same way as today: server clamps `limit` to 1..1000, client pages via `PAGE_SIZE` + `limit+1` lookahead (`worktrees.rs:1814`, `VcsPanel.tsx:221-225,292-300`) — identical cost profile to the worktree case.
- One UI change: hide `VcsPanel`'s "Diff from `<baseBranch>`" toggle (`VcsPanel.tsx:484`) when `scope === "project"`, since it's meaningless when nothing is off-branch.
- Explicitly out of scope: deriving a synthetic base (e.g. a project's default branch) for direct sessions — ambiguous, and can be layered on later as an annotation without changing the route shape, since `list_commits` already takes `Option<base_sha>`.
